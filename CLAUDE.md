# Organizer — Project Memory

## Purpose & Vision

"Organizer" is a mobile daily-schedule app (Flutter, Android + iOS). Long-term vision: the app knows the user's daily/hourly schedule (gym in the morning, meeting at noon, meeting friends in the evening) and reminds them what to do and where to be.

## Session 2026-07-22: v2 reminders, sets count, Sleep + overnight events, GC-style views, analysis periods

- [x] **Local notifications** (per-event picker chosen by user over global default): `Event.reminderMinutes` int? (null = off, 0 = at start; JSON key `reminder`, omitted when null — old data loads fine). Add/edit sheet has a "Reminder" ChoiceChip row (Off / At start / 5 / 10 / 30 min / 1 hour); **new events default to 10 min**, edits keep the saved value. Timeline bubbles get a small `Icons.notifications` marker; details dialog shows "Reminder X min before". Undo-delete restores the reminder.
- `services/notification_service.dart`: wraps `flutter_local_notifications` (+ `timezone`, `flutter_timezone` for tz.local). `EventStore` takes an optional `NotificationService` (null in tests/web) and calls scheduleFor/cancelFor on add/update/remove; `load()` does cancelAll + rescheduleAll so the OS queue always mirrors stored data. Notification ids = FNV-1a 31-bit hash of the event id (stable across restarts). Weekly-recurring events use `matchDateTimeComponents: DateTimeComponents.dayOfWeekAndTime` anchored at the next future occurrence — one schedule covers the series. Exact alarms tried first (`exactAllowWhileIdle`), falls back to inexact on PlatformException. Android 13+ notification + exact-alarm permissions are requested lazily on first schedule, not at launch.
- **Web is a no-op**: every service method returns early on `kIsWeb` (plugin has no web support). Chrome stays the UI preview; actual notifications must be verified on the Android phone (`flutter run -d <device>`), which had NOT been done yet as of this session — UI + analyze + test + `flutter build apk --debug` all verified.
- Android setup: manifest got POST_NOTIFICATIONS / RECEIVE_BOOT_COMPLETED / SCHEDULE_EXACT_ALARM permissions + the plugin's ScheduledNotificationReceiver and boot receiver; `app/build.gradle.kts` got core library desugaring (`isCoreLibraryDesugaringEnabled = true` + `desugar_jdk_libs:2.1.4`) which the plugin requires.
- **API gotchas hit**: flutter_local_notifications **v22** uses named parameters everywhere — `initialize(settings: ...)`, `cancel(id: ...)`, `zonedSchedule(id:, scheduledDate:, notificationDetails:, androidScheduleMode:, ...)`. flutter_timezone **5.x** returns a `TimezoneInfo` object (use `.identifier`), not a String.

- [x] **Overnight events** (user request 2026-07-22, chosen over "log on wake-up day" for Sleep tracking): **end < start now means the event ends the next day** (end == start is the only invalid combo — form SnackBar). No JSON change — same hour/minute fields, just reinterpreted; old data (always end > start) is unaffected. Model: `isOvernight`, `durationMinutes` (wraps midnight), `startsOn(day)` (old isOn logic), `isOn(day)` = startsOn OR the morning tail (startsOn(day−1) && overnight — works for weekly recurrence too), and `segmentOn(day)` returning that day's portion in minutes-from-midnight. Day timeline renders the clipped segment (evening bubble on start day, morning bubble on next day; bubble label still shows real times); `eventsOn(day)` sorts by segment start so tails sort at 00:00; overlap clustering uses segments. Form shows an "Ends the next day" hint under the time row when end < start, and keep-duration-on-start-move is mod-24h. Week stats count each day's clipped minutes (donut/day bars split overnight events across both days); drill-down lists each occurrence once on its start day (plus Monday tails from the previous week); gym session duration = full durationMinutes. Details dialog appends "(next day)". Unit tests in test/event_test.dart cover isOn/segmentOn/duration incl. recurring tails.

## Architecture

- **Flutter 3.44.4 stable**, Material 3, `ColorScheme.fromSeed(seedColor: Colors.teal)`. No custom assets; standard Material icons only.
- **Dependencies:** `shared_preferences` (persistence), `intl` (date formatting), and since v2 `flutter_local_notifications` + `timezone` + `flutter_timezone` (reminders). Deliberately no state-management or calendar packages — all grids are hand-rolled.
- **Storage decision:** all events JSON-encoded into a single shared_preferences key (`organizer_events`). Chosen over sqflite because it works identically on web (Chrome live preview), Android, and iOS with zero native setup. Fine for v1 volumes; migrate to drift/sqflite only if event counts or querying needs grow. Event dates serialize as `y-m-d` string + hour/minute + endHour/endMinute ints (see `Event.toJson`). `Event.fromJson` tolerates missing endHour (pre-range data) by defaulting to start + 1h.
- **State:** `EventStore extends ChangeNotifier` (in `services/event_store.dart`) is the single source of truth, created in `main.dart`, passed down by constructor; the whole view area rebuilds via one `ListenableBuilder` in HomeScreen. Event ids are `millisecondsSinceEpoch_counter`.
- **Navigation:** a single `HomeScreen` holds `_selectedDate` + a `CalendarView` enum (day/week/month/year) switched with a Material 3 `SegmentedButton`. Month-day tap → Day view; Year-month tap → Month view; Week-day-header tap → Day view. The only "route" is the add-event modal bottom sheet.

### File map (lib/)
- `main.dart` — entry; creates NotificationService (init) + EventStore, awaits `store.load()`, theme
- `models/event.dart` — Event (id, date, start/end TimeOfDay, title, category, notes, repeatsWeekly, reminderMinutes) + JSON + overnight helpers (`isOvernight`/`durationMinutes`/`startsOn`/`isOn`/`segmentOn`)
- `models/workout_notes.dart` — gym-notes text format: `workoutTypes`, `builtInExercises`, `parseWorkoutNotes` (shared by add_event_sheet + stats_screen)
- `services/event_store.dart` — `eventsOn(day)` (sorted by that day's segment), `hasEventsOn`, add/update/remove/load/_save, notification wiring
- `services/notification_service.dart` — flutter_local_notifications wrapper (schedule/cancel/rescheduleAll, kIsWeb no-op)
- `screens/home_screen.dart` — SegmentedButton switcher, Today button, FAB, hosts the 4 views
- `screens/stats_screen.dart` — Analysis: period selector (Day/Week/Month/Year), donut, category drill-down, adaptive bar list
- `widgets/time_grid.dart` — shared `TimeGrid` (24h hour-gutter grid; `labelStepHours`, `fitToHeight`, `TimeGridGeometry`), `NowLine`, `layoutEventColumns` overlap algorithm
- `widgets/event_details_dialog.dart` — `showEventDetailsDialog` (info + Edit + Delete/Undo), used by Day bubbles and Week chips
- `widgets/day_view.dart` — `DayView`/`DayTimeline` (positioned `_EventBubble`s on TimeGrid; hourly labels, scrolls)
- `widgets/week_view.dart` — GC-style 7-column week grid on TimeGrid: 6h gutter labels, fitToHeight (`_WeekHeader`, `_WeekEventChip`)
- `widgets/month_view.dart` — month header + reusable `MonthGrid` (Monday-first, `dayBuilder`, optional `includeAdjacent`) + chip-based `_MonthDayCell` — YearView reuses `MonthGrid`
- `widgets/year_view.dart` — GridView of 12 `_MiniMonth`s built on `MonthGrid`, heat-tinted tappable days
- `test/widget_test.dart` — smoke test (uses `SharedPreferences.setMockInitialValues`)
- `test/event_test.dart` — Event unit tests (overnight/segment/recurrence date math)

## Mistakes & Hard Parts

- **Environment (2026-07-21):** `flutter doctor` — Android toolchain + Chrome OK, but **Xcode installation incomplete and CocoaPods missing** on this Mac. iOS builds are blocked until the user installs Xcode from the App Store, runs `sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer && sudo xcodebuild -runFirstLaunch`, and installs CocoaPods (`sudo gem install cocoapods` or `brew install cocoapods`). Not a v1 blocker (dev preview = Chrome, deploy = Android).
- **Hot reload from scripts:** `flutter run -d chrome --pid-file <file>` lets you trigger hot reload with `kill -USR1 $(cat <file>)` and hot restart with `kill -USR2 ...` — no stdin needed. Web hot reload works on Flutter 3.44. Gotcha: changes to `main()` itself, or adding/removing fields on existing classes (e.g. the Event model refactor), get "hot reload rejected" — use hot **restart** (USR2) for those.
- **flutter create default test** references the demo `MyApp` counter — must be replaced when you replace main.dart, or `flutter test`/`analyze` break.
- No other significant problems in v1 — kept dependency surface tiny on purpose.

## How to Run

- **Live dev preview (Chrome):** `flutter run -d chrome` — web is preview-only, not a release target. For script-driven hot reload add `--pid-file /tmp/flutter.pid` and `kill -USR1 $(cat /tmp/flutter.pid)`.
- **Real Android phone:** enable Developer Options + USB debugging on the phone, connect via USB (accept the RSA prompt), `flutter devices` to confirm it's listed, then `flutter run -d <device-id>`.
- **APK:** `flutter build apk --release` → `build/app/outputs/flutter-apk/app-release.apk` (debug variant verified working this session).
- **Tests / lint:** `flutter test` (4 tests: widget smoke + Event overnight/recurrence math), `flutter analyze` — both clean as of end of the 2026-07-22 session.
- **iOS:** blocked until Xcode + CocoaPods installed (see Mistakes & Hard Parts); the `ios/` platform folder already exists, so `flutter run` on an iPhone should work once the toolchain is fixed.
