# Organizer — Project Memory

## Purpose & Vision

"Organizer" is a mobile daily-schedule app (Flutter, Android + iOS). Long-term vision: the app knows the user's daily/hourly schedule (gym in the morning, meeting at noon, meeting friends in the evening) and reminds them what to do and where to be.

## Next Direction: Personal Hub (agreed with the user 2026-10-18; daily quiz built the same day)

The user wants Organizer to become his single personal hub: see and manage what he did each day, how long he worked, his steps and his meetings; plan the week and look back; take a daily quiz on his master's courses; send voice notes to his "second brain" — "everything in one place". Hard constraints: **no paid APIs, no extra fees, no server.** A VPS was considered and dropped: notifications already work on the phone, step data can only be read on the phone, and the only VPS available is a shared work machine (personal data must not go there).

## Architecture

- **Flutter 3.44.4 stable**, Material 3, `ColorScheme.fromSeed(seedColor: Colors.teal)`. No custom assets; standard Material icons only.
- **Dependencies:** `shared_preferences` (persistence), `intl` (date formatting), and since v2 `flutter_local_notifications` + `timezone` + `flutter_timezone` (reminders); since the quiz `http` (GitHub API — also works in the Chrome preview, unlike `dart:io`) + `flutter_secure_storage` (the token). Deliberately no state-management or calendar packages — all grids are hand-rolled.
- **Storage decision:** all events JSON-encoded into a single shared_preferences key (`organizer_events`). Chosen over sqflite because it works identically on web (Chrome live preview), Android, and iOS with zero native setup. Fine for v1 volumes; migrate to drift/sqflite only if event counts or querying needs grow. Event dates serialize as `y-m-d` string + hour/minute + endHour/endMinute ints (see `Event.toJson`). `Event.fromJson` tolerates missing endHour (pre-range data) by defaulting to start + 1h.
- **State:** `EventStore extends ChangeNotifier` (in `services/event_store.dart`) is the single source of truth, created in `main.dart`, passed down by constructor; the whole view area rebuilds via one `ListenableBuilder` in HomeScreen. Event ids are `millisecondsSinceEpoch_counter`.
- **Navigation:** a single `HomeScreen` holds `_selectedDate` + a `CalendarView` enum (day/week/month/year) switched with a Material 3 `SegmentedButton`. Month-day tap → Day view; Year-month tap → Month view; Week-day-header tap → Day view. The only "route" is the add-event modal bottom sheet.

## Mistakes & Hard Parts

- **Environment (2026-07-21):** `flutter doctor` — Android toolchain + Chrome OK, but **Xcode installation incomplete and CocoaPods missing** on this Mac. iOS builds are blocked until the user installs Xcode from the App Store, runs `sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer && sudo xcodebuild -runFirstLaunch`, and installs CocoaPods (`sudo gem install cocoapods` or `brew install cocoapods`). Not a v1 blocker (dev preview = Chrome, deploy = Android).
- **Hot reload from scripts:** `flutter run -d chrome --pid-file <file>` lets you trigger hot reload with `kill -USR1 $(cat <file>)` and hot restart with `kill -USR2 ...` — no stdin needed. Web hot reload works on Flutter 3.44. Gotcha: changes to `main()` itself, or adding/removing fields on existing classes (e.g. the Event model refactor), get "hot reload rejected" — use hot **restart** (USR2) for those.
- **flutter create default test** references the demo `MyApp` counter — must be replaced when you replace main.dart, or `flutter test`/`analyze` break.
- No other significant problems in v1 — kept dependency surface tiny on purpose.
- **Pub cache pruned (seen 2026-10-18):** analyze said `package:intl` doesn't exist and tests failed to load with "Matrix4 isn't defined" — the packages in `~/.pub-cache` had been deleted since July. `flutter pub get --enforce-lockfile` restores them without touching `pubspec.lock`.
- **Signing = this Mac's `~/.android/debug.keystore`** (release builds too, see `android/app/build.gradle.kts`). Android only accepts updates signed with the same key, and `flutter run` answers a failed install by uninstalling the old app — wiping every event, since they live only on the phone. Keep a backup of that keystore and use it on any other build machine; when unsure, install with `adb install -r <apk>` (fails loudly) instead of `flutter run`.

## How to Run

- **Live dev preview (Chrome):** `flutter run -d chrome` — web is preview-only, not a release target. For script-driven hot reload add `--pid-file /tmp/flutter.pid` and `kill -USR1 $(cat /tmp/flutter.pid)`.
- **Real Android phone:** enable Developer Options + USB debugging on the phone, connect via USB (accept the RSA prompt), `flutter devices` to confirm it's listed, then `flutter run -d <device-id>`.
- **APK:** `flutter build apk --release` → `build/app/outputs/flutter-apk/app-release.apk` (debug variant verified working this session).
- **Tests / lint:** `flutter test` (11 tests: widget smoke, non-gym notes survive an edit, Event overnight/midnight/recurrence math, quiz), `flutter analyze` — both clean as of 2026-10-18.
- **iOS:** blocked until Xcode + CocoaPods installed (see Mistakes & Hard Parts); the `ios/` platform folder already exists, so `flutter run` on an iPhone should work once the toolchain is fixed.
